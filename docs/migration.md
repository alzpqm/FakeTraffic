# 安裝、升級與回復

本文件適用具有共同設定頁及單一 `faketraffic` 服務的版本（0.2.0 起）。
0.1.0 的唯讀入口與新版不同，不可混用兩代套件。

## 套件與安裝前檢查

從 [Releases](https://github.com/alzpqm/FakeTraffic/releases) 下載目標系統相符的核心、LuCI 及校驗清單。
核心與介面應使用同一產品版本；需要可選 eBPF 的版本，再準備相符的後端包。
所有系統依賴必須與韌體／核心相符，不使用 `force-depends` 或 `force-overwrite`。

1. 在受限位置保存設定、套件版本、服務啟用狀態及離線回復套件；不要公開備份。
2. 核對 SHA256SUMS、架構與系統版本，確認沒有待套用的 UCI 變更。
3. 使用 `apk add --simulate --allow-untrusted` 加上欲安裝的檔案預覽交易。
4. 若交易涉及預期外的升降級、移除或網路系統套件，停止操作，先解決相依問題。

全新安裝不自動啟用服務。安裝後在 LuCI「服務 → FakeTraffic」設定介面、TCP／UDP、
偽裝內容與參數，儲存套用並確認實際運行狀態。

## 從 FakeHTTP／FakeSIP 或舊共同入口遷移

新版核心包含自己的引擎，使用 `/etc/config/faketraffic` 與 `/etc/init.d/faketraffic`。
原有獨立服務與新版不可同時注入。

1. 先備份原設定並準備回復套件，審查新設定如何對應原本兩個引擎。
2. `tools/prepare-migration.sh` 可產生受限目錄內的候選合併設定，不直接套用。
   遇到額外 section 或無法對應的設定時，應人工處理，不能靜默丟棄。
3. 安裝新版後，明確停止及停用舊獨立服務；確認原程序、queue／自有規則已退出，才啟動新版。
4. 核對實際狀態、設定與一般連線。確認新版可用前，保留停用的舊套件及備份。
5. 若要移除舊套件，先模擬交易；只移除指定的舊產品套件，不自動清理其他系統依賴。

服務切換可能短暫停止偽裝；不要為此重啟整個網路、清空全域防火牆或更改其他代理設定。

## 升級與後端切換

核心、LuCI 介面與已安裝的 eBPF 套件有精確版本相依，必須同版本、同一筆交易升級。
未安裝 eBPF 的系統更新核心與介面兩包；已安裝 eBPF 的系統更新三包，
即使目前實際選用 NFQUEUE 也一樣。首次安裝命令見 [README](../README.md#首次安裝)。
不要先更新核心再補後端，也不要為了通過交易而強制忽略相依或自行移除後端。

升級前正常停止本服務。若使用的版本具有 eBPF 後端，應確認自有 checkpoint 已乾淨退出；
未知程序或殘留 checkpoint 需要先查明，不能盲刪 marker、TC filter 或繞過檢查。
更新相符套件後再啟動，確認已儲存設定、原開機啟用狀態與實際運行後端一致。
升級保留既有設定；安裝 eBPF 套件並不會自動把後端切換成 eBPF。

支援 eBPF 的版本仍保留 NFQUEUE 選項。先檢查相容性預檢及語義差異；預檢通過不等於
核心已成功載入／掛載，也不會自動刪除不相容的 payload 或同時啟動兩種後端。

## 回復

先乾淨停止新版，再依備份恢復相符套件、設定及原服務啟用狀態，確認程序及連線。
回復前應核對設定是否在升級後又被修改，避免覆寫後來的變更。

多模板設定不能直接交給只支援單模板的舊版本。降版前需準備可表示該設定的舊版配置及啟動方式；
無法完整恢復時應停止降版，不以刪除使用者模板或放寬安全檢查讓回復看似成功。

設定、自訂 payload、診斷輸出與日誌可能含位址、URI 或實例識別；對外回報問題前請先去敏。
