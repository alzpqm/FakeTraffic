# 後端選擇

FakeTraffic 由同一個 LuCI 頁面及服務管理所選後端，不需要同時管理兩套注入服務。

| 項目 | NFQUEUE | 可選 eBPF |
| --- | --- | --- |
| 核心處理 | 保留 FakeHTTP／FakeSIP 引擎 | 由 TCX 與受控 builder 處理 |
| 安裝 | 核心與 LuCI | 再加相符後端及核心依賴 |
| 設定 | 保留兩協定的既有細項 | 不相容設定由預檢拒絕 |
| 模板 | 依兩引擎原有清單行為 | 每協定最多 16 份，按觸發輪替 |
| 計數 | 各引擎計數 | 部分注入計數由 TCP／UDP 共用 |

NFQUEUE 為預設選項。eBPF 需要 Linux 6.6+、TCX 及匹配依賴；不能只因名稱或支援項目較多
就視為等價替換。兩者的觸發方向、狀態窗口、跳過策略與模板內容可能不同。
切換前請檢查相容性預檢與語義提示，不支援的設定不會靜默刪除或改寫。

服務採互斥後端所有權；切換時先乾淨停止原後端，不能以兩套並行當成回退。
預檢是唯讀能力檢查，不代表 BPF 已實際載入或掛載成功。

統計用於本機排錯，不可把 queue、clone、submit、捕獲與遠端送達視為同一指標。
本專案不據單一計數或程序資源值宣稱效能、DPI 或相容性優勢。
